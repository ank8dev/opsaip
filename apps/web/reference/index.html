                  Agents

                  Claude Code and Codex connect to the Opsaip MCP server and report what they do. Opsaip never logs into anyone’s account.

                  Opsaip MCP serverThe address every agent connects to.
                  https://opsaip.example/mcp
                  Connect an agentEach teammate runs this once and signs in. The sign-in token tells Opsaip whose agent is reporting.
                  claude mcp add --transport http opsaip https://opsaip.example/mcp
                  How agents get tasksAn MCP server can only answer, it can’t start an agent. So something has to start the work.
                  Report with hooksClaude Code hooks report start, progress and finish on every event, so nothing depends on the model remembering. Codex reports through AGENTS.md.
                  Mark an agent offline afterWith no heartbeat for this long, the agent shows as Offline and its running tasks as Stalled.
                  Chat transcriptsWhat an agent sends from its chat. Full transcripts fill the chat view but can contain code and secrets.

                  Approvals

                  Before these actions an agent calls ask_human: the task stops and shows up under Needs you until someone answers.

                  Deploy to productionAnything users will see.
                  Merge a pull requestEven where GitHub would allow it.
                  Run a database migrationChanges to data are the hardest to undo.
                  Delete outside the taskBranches or files the task didn’t create.
                  Add a dependencyA new package in the project.
                  Who can approveThe person who answers the agent’s question.
                  If nobody answersAn agent waiting for approval does nothing, so a forgotten question blocks the task.

                  Tool servers

                  MCP servers Opsaip itself calls to act in your tools. Start with read only and give write access once you trust the flow.

                    Add a tool serverAny service with an MCP server: Sentry, Stripe, Figma and so on.

                    Sync

                    Opsaip keeps each task in step across Linear, GitHub and Notion. Every field has one tool that owns it; the others follow. Plain code does the routine syncing; Opsaip AI only proposes the status mapping and suggests links.

                    Source of truth

                    StatusFor code tasks, real pull requests are the most honest signal, so status can’t drift from the code.
                    Priority and sprintPlanning stays where the team plans.
                    Description and notesLong text lives in docs; the others get a link.
                    AssigneeOpsaip assigns people and agents, then writes it everywhere.

                    Status mapping

                    Each tool names its states differently. Proposed by Opsaip AI from your Linear workflow and Notion Status options — check it before sync goes live.

                    OpsaipLinearGitHubNotion
                    Propose the mapping againRun this after you change states in Linear or Status options in Notion.

                    Per tool

                    LinearOpsaip reads changes and writes status back.
                    GitHubRead only: a pull request’s state comes from the real PR, Opsaip never fakes it.
                    NotionOpsaip reads changes and writes status back.

                    When tools disagree

                    ConflictsAsk while you build trust in the mapping; later the source of truth can win on its own.
                    Suggest links with AIWhen a PR, issue or page looks like it belongs to a task (same branch, id or title), Opsaip suggests linking it. You confirm.
                    Catch-up checkWebhooks bring changes right away; this check finds any that got lost.
